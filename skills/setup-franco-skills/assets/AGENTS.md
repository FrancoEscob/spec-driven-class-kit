# Reglas de esta práctica

- Trabajamos en español y explicamos las decisiones sin exigir conocimientos técnicos.
- Primero entendemos el producto. La spec describe qué debe pasar; el plan explica cómo construirlo.
- Guardamos cada proyecto en `specs/<nombre>/`: decisiones.md, spec.md, plan.md, tickets/ y evidencia.md, a medida que se necesiten.
- Los tickets son archivos Markdown locales. Cada uno entrega un resultado comprobable e indica sus dependencias.
- Leé las skills solicitadas desde su carpeta instalada. `no-tecnico` puede acompañar la entrevista, el plan y la implementación.
- No marques un criterio cumplido sin evidencia ejecutada. Lo que falta comprobar se registra como pendiente.
- TDD es opcional: no es requisito para practicar SDD. Las comprobaciones de los criterios sí forman parte del trabajo.
- Respetá el alcance del ticket y las decisiones del usuario. Preparar skills o especificar no implica implementar.
